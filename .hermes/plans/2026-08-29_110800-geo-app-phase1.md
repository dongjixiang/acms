## Proposed Approach

**Phase 1 6 周排期**（按多多决策 C：DeepSeek✅ + 3 个 P0 引擎 + 4 个 P1 引擎 + 24 P0 能力）：

```
Week 1: 引擎接入 — P0 三件套（OpenAI/Claude/Perplexity）
Week 2: 引擎接入 — P1 四件套（Gemini/Copilot/Grok/Google AI Mode）+ 反爬绕过
Week 3: 数据采集 + 分析核心
Week 4: 优化 + 执行（agent pipeline）
Week 5: 监控 + 系统管理（agency 多品牌）
Week 6: 报告 + 工作流集成 + 端到端测试
```

**关键设计决策**：
1. **引擎抽象层扩展**：现在 `engine.query()` 返回 `{ok, text, latency_ms, usage}`，需扩展到 `{ok, text, citations, latency_ms, usage, model}`，让 Perplexity 的引用数据可用
2. **agent pipeline**：用 ACMS 现有 orchestrator/worker（agent-store + tool-store），不造新 agent runtime
3. **数据流**：每周 cronjob 跑 tracker agent 收集数据 → 周六跑 reporter agent 生成报告
4. **UI 演进**：8 个 tab 逐步填数据，从静态「空壳」到动态图表

## Risks, Tradeoffs, and Open Questions

### 风险

1. 🔴 **AI 引擎反爬** — ChatGPT/Perplexity 会封号，需 proxy 池 + 速率控制（Week 2 必须验）
2. 🟡 **Google AI Mode 不可 API 调用** — 只能 web scraping，Google 反爬严，可能完全做不了（fallback：标记「待 Phase 2」）
3. 🟡 **数据真实性差异** — 不同账号/地区/时间 AI 回答不一致，需多账号采样（Week 3 验证）
4. 🟢 **LLM 优化幻觉** — Qwen 改写可能破坏原意，需人工审核兜底（Week 4 验证）

### 待多多确认（影响 Phase 1 设计）

1. **引擎调用频率限制** — 每引擎每分钟最多 N 次（防被 ban）。N 选多少？
2. **数据保留期限** — geo_responses 保留多久？（30 天 / 90 天 / 永久？）
3. **报告推送渠道** — Email / Webhook / 命令面板？（Email 已有但需复用什么）
4. **多品牌数据隔离策略** — 按 user_id 隔离？按 workspace 隔离？

### 权衡（已决策，无需再问）

- 自托管 vs SaaS：**自托管**
- 多品牌管理：**agency 模式**
- 主题系统：**独立深色**
- 数据库：**SQLite**
- 引擎覆盖：**8 个全做**（但优先级混合：4 P0 + 4 P1）
- 任务追踪：**不进 Kanban，写 plan**
