PR-W  Word Ribbon + OfficeDocEditor instance API + 视觉

  • 视觉: Calibri 字体 + paper 880px 卡片 + 24px padding + box-shadow
  • heading 字号: H1=2em H2=1.5em H3=1.25em + margin
  • 引用块: 4px 色条 + italic + 圆角

PR-W2  块级 formatting + 行内格式 + 状态栏
  • 治根: schema 已有 parseInline 函数 (8 个月前写但 UI 没用过), 接入渲染层
  • instance API 扩 3 个: getBlockFormatting / setBlockFormatting / toggleInlineFormat
  • Word Ribbon 16→32 按钮: 加 B/I/U/code 格式组 + 12/14/16/18/24 字号组 + Sans/Serif/Mono 字体组 + 左/中/右/两端 对齐组
  • Word 状态栏: 页码/字数/块数/缩放 (学 OO statusbar.less)
  • CSS: .ode-align-{left,center,right,justify} / .ode-fs-{12-30} / .ode-ff-{serif,sans,mono}

PR-W3  隐藏"字段化" UI (治根)
  • 根因: type-badge 永远显示 + "+ 添加块"按钮永远显示 → 用户感觉"在填字段"
  • .ode-type-badge: 默认 opacity:0 + pointer-events:none, hover 才出
  • .ode-add-end: 默认 opacity:0, .ode-block-list:hover 或 .ode-add-end:hover/focus 才出
  • .ode-block padding 2px → 0 (段落完全无视觉分隔, 像 Word)

PR-W4  Markdown Shortcut (Notion/OO 体验)
  • 治根 bug: bindContentEvents 在 mountEditor 外, 不能闭包访问 focusBlock
  • 修复: inline find DOM + focus, 暴露 scope 隔离问题
  • 7 个 markdown shortcut:
    # + 空格 → H1, ## → H2, ### → H3
    * 或 - + 空格 → bullet list
    1. + 空格 → numbered list
    [] + 空格 → todo, > + 空格 → quote, ``` + 空格 → code
  • heading 后 Enter 自动转普通段落 (OO Word 行为)

PR-W5  Word 文档"页面化" 视觉 (纯 CSS)
  • heading 加大 margin (H1: 1em top 0.4em bottom, H2: 0.8em top)
  • paragraph line-height 1.7 (Word 默认)
  • paper 卡片 4 层 box-shadow (1px + 4px + 12px + 0px) 模拟多纸叠感
  • 段落间 padding-top 4px (相邻同类型 block)

PR-W6  选中文本浮动工具栏 (Bubble Menu) (1 天)
  • 100 行 module-level IIFE
  • 监听 selectionchange → 选区上方浮动 4 按钮 (B / I / U / </>)
  • 用 document.execCommand('insertText') 替换选区
  • 已包检测 → toggle 行为
  • 跟 markdown shortcut 互补: shortcut 是全文本, bubble menu 是选区

核心复用模式 (供未来 Office 改造)
═══════════════════════════════════════════

1. ACMSRibbon 极简组件 (147 行覆盖 OO TabBar.js 728 行核心功能)
   - create(host, {tabs, groups, buttons, active}) → {setActive, setButtonActive, destroy}
2. ops 对象模式: Ribbon 按钮 + 标题栏按钮共用同一组操作函数
3. instance API 暴露模式: mount 返回的不只是"读"接口, 还要"写/改"接口
4. closure scope hoisting: 内层函数(instance 创建) 调外层辅助函数(save 等) 必须提升变量
5. schema 已有但 UI 没用过的功能 (parseInline), 接入渲染层即可
6. data 引用切换模式 (sheets[].data 缓存到 closure var, 切 sheet 重新指向)
7. var(--bg2, fallback) 模式: 主题感知 CSS, dark 主题下自动跟随
